The Problem

Powerful, but invisible

CCPI's search was built for power users who already knew how to translate project intent into filter logic. Everyone else needed a rep, or hours of trial and error.

89% of paid users who searched took meaningful action. The other 11% abandoned before getting there — a gap with clear revenue implications at scale. A competitor's AI-powered search launch shifted market expectations and added urgency.

CCPI's filter system was powerful but invisible to users who didn't already know how to use it.

Discovery

The leap-of-faith assumption

Would users want natural language search alongside filters — not instead of them?

Needs data Discovery interview count, segments (trade contractors, GCs, building product manufacturers), key questions asked, and CDH-framework insights.

A signal that changed direction

Named project lookups — searching for a specific project by name or partial description — accounted for roughly 40% of queries. The existing filter UI couldn't serve these at all.

Prior evidence

Ask Documents, a separate AI panel feature, had already shown CCPI users respond to AI-assisted workflows when the interface feels conversational rather than transactional.

Process

From assumption to functional prototype

  • Story mapping — mapped the end-to-end journey in Miro, surfacing where intent-to-action handoff was breaking down
  • Assumption risk matrix — with PM Darcy, classified NL-to-filter mapping as the highest-risk, highest-value assumption
  • Figma mocks — default, active, parsed results, Filtered By panel, suggestion states
  • Prototype in Cursor — functional HTML/JS prototype mapping NL queries live to CCPI's filter taxonomy (trade/CSI, location, bid stage, timeline, project value); tested search-only vs. search + filters
Needs data Usability testing — participant count, method (UserTesting / moderated), key tasks tested, top 2–3 findings.

Key Design Decisions

Conversational, not transactional

A chat-based interface that lets users build searches iteratively through natural language — clarifying questions, suggestions, visible reasoning. Users shouldn't need to know CCPI's filter taxonomy to get good results.

Transparency over magic

When Search Assist maps a query to filters, it shows its work. Users can see which filters were applied and why, and adjust them. AI that explains itself earns more adoption than AI that just produces results.

Distinguishing two AI features

A critical decision was separating Search Assist from hybrid vector search — a simultaneous, separate feature. Both touch the same search input but serve different mental models.

Phased rollout by design

Built to support a controlled beta — closed to 10 customers first, then a percentage of new users — so learnings could inform prompt refinement and latency improvements before broad release.
