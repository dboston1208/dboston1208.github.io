01 Overview

Design debt rarely announces itself. It accumulates quietly — a pill background that's close but not quite right, a filter button using text where the spec calls for an icon, a mobile drawer behavior that was never implemented. Individually minor. Together, they erode the credibility of the design system.

This was a systematic audit of the live CCPI search results experience against updated Figma specs, across desktop, tablet, and mobile, to document exactly where live behavior diverged from design intent.

When a feature ships, does what users experience match what the design specified? If not, what's different — and does it matter?
02 My Role

I authored the updated Figma specs for the applied filters component across all breakpoints, conducted the live-vs-spec comparison, severity-rated every discrepancy, and triaged findings with PM Darcy to separate intentional deviations from implementation gaps. The output is a structured issue list engineering can prioritize directly.

03 Approach

Computed values, not eyeballs

Rather than a visual comparison, the audit extracted exact CSS values from the live application and compared them directly against spec. This removed ambiguity: either the values matched or they didn't. Coverage ran across four breakpoints — 1440px desktop (default and sidebar states), 768px and 600px tablet (layout row structure), and 375px mobile (filter panel behavior).

04 What the Audit Found

Eight discrepancies, severity-rated. The full set:

SeverityDiscrepancy
CriticalMobile filter panel opens as the desktop sidebar instead of the specced 300px drawer overlay
CriticalSidebar doesn't auto-collapse at smaller viewports, covering pills, search bar, and results on load
CriticalPills keep the full category label at 375px instead of the specced short form
IncorrectFilter button is a text button, not the specced funnel icon with counter badge — a different component, not a styling miss
IncorrectClear All missing from its inline position in the pills row; only reachable inside the sidebar
MinorPill background rgb(244,244,244) vs specced #e7e6e5, all breakpoints
MinorTablet rows stack separately instead of consolidating into one row per spec
MinorSection headers (Company / Project Filters) omitted — pending confirmation whether intentional

The one that matters most

The mobile drawer is the audit's headline finding. The spec defines a right-edge drawer at 375px — 300px wide, with a header, close button, active filter count, Clear All, section headers, and a sticky Apply button. The live implementation opens the full desktop sidebar at every viewport width. Combined with the auto-collapse failure, applied filters are effectively invisible to a mobile user on load. That's not polish debt; it's a functional regression.

05 Triage with the PM

Not every discrepancy is a bug. Some reflect intentional decisions made during build that were never backported to the spec. The triage session with PM Darcy separates three buckets: ship-blocking issues, backlog issues, and intentional deviations where the spec is what needs updating.

That third bucket is the underrated one. A spec that silently drifts from the product stops being a source of truth, and every future audit inherits the noise.

07 Why This Is Design Work

Most portfolios show the work that goes into making something. This is the work that ensures it stays made. QA at this level — computed value comparison, breakpoint by breakpoint, triaged with stakeholders — is what separates a designer who hands off Figma files from one who takes ownership of the full outcome. The component isn't done when the spec is approved. It's done when what users see matches what was designed.

It also surfaced something true about design at scale: the spec is only as useful as the process for enforcing it. Finding these gaps was valuable. Having a repeatable method for finding them is more valuable.

08 Reflection

What worked: Computed style inspection removed subjectivity from the process. When you can show rgb(244,244,244) next to #e7e6e5, the conversation with engineering is faster and cleaner.
