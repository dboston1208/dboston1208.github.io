The Problem

Design debt rarely announces itself.

It accumulates quietly — a pill background color that's close but not quite right, a filter button that uses text where the spec calls for an icon, a mobile drawer behavior that was never implemented. Individually minor. Together, they erode the credibility of the design system.

This was a systematic audit of the live CCPI search results experience against updated Figma specs — across desktop, tablet, and mobile — to document exactly where live behavior diverged from design intent.

When a feature ships, does what users experience match what the design specified? If not, what's different — and does it matter?

My Role

Owned specs through triage

  • Authored updated Figma specs for the applied filters component across all breakpoints
  • Conducted a systematic live-vs-spec comparison using computed style inspection, not visual eyeballing
  • Documented and severity-rated every discrepancy found
  • Triaged findings with PM Darcy to separate intentional deviations from implementation gaps
  • Produced a structured issue list for engineering prioritization

Approach

Computed values, not eyeballs

Rather than a visual comparison, the audit extracted exact CSS values from the live application and compared them directly against spec. This removed ambiguity: either the values matched or they didn't.

What We Found

8 discrepancies, three severity levels

CriticalMobile filter panel opens as desktop sidebar

Spec calls for a right-edge drawer overlay at 375px — 300px wide, with header, close button, active filter count, Clear All, section headers, and a sticky Apply button. Live implementation opens the full desktop sidebar at every viewport width.

CriticalSidebar doesn't auto-collapse at smaller viewports

When the sidebar defaults open at 768px or 375px, it covers the filter pills row, search bar, and left portion of the results table. A functional regression — applied filters are invisible on load.

CriticalPills render with category label at mobile

Spec strips the category prefix at 375px to save space (Last 90 Days ×). Live keeps the full label (Last Updated: Last 90 Days ×) regardless of breakpoint.

IncorrectFilter button format doesn't match spec

Spec: funnel icon + filled blue counter badge. Live: text button reading "Filters (1)" — a different component pattern entirely, not a styling mismatch.

IncorrectClear All missing from inline position

Spec places Clear All inline in the pills row. Live only shows it inside the sidebar — invisible when the sidebar is closed.

MinorPill background color mismatch

Spec: #e7e6e5. Live: rgb(244, 244, 244) — slightly lighter, present across all breakpoints.

MinorLayout row structure at tablet

At 600–768px, spec consolidates filter button, context selector, and search input into one row with pills below. Live stacks them into separate rows.

Triage with Darcy

Not every discrepancy is a bug

Some reflect intentional decisions made during build that weren't backported to the spec. The triage session separated ship-blocking issues, backlog issues, and intentional deviations requiring a spec update.

Reflection

What worked

Computed style inspection rather than visual comparison removed subjectivity from the process. When you can show rgb(244,244,244) vs #e7e6e5 side by side, the conversation with engineering is faster and cleaner.

What I'd do differently

Needs data e.g. establish a QA checkpoint earlier in the build cycle, create a shared breakpoint checklist with engineering, involve Activators earlier on mobile behavior expectations.
